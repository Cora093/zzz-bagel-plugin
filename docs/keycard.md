# 开房卡

开房卡模式在城郊幻境高危局带一张门禁卡入场，走到对应房间刷卡进门，只搜房间内的容器后退出。本文集中说明开房卡专属的数据和执行规则；与跑刀共用的部分只给链接。

当前实现范围：

| 部分 | 状态 |
| --- | --- |
| 房卡门点类型与刷卡处长按 | 已实现，见[刷卡处](container.md#刷卡处) |
| 房间清单、入口段与房间段、拼接与开启选择 | 已实现，本文下面各节 |
| 编辑器的分组、开关、新增、录制与试跑 | 已实现，见[网页路线编辑器](editor.md#开房卡的段) |
| 配置 `mode`、`keycard_room`、`keycard_reserve`，启动检查、城郊幻境入场、带卡核对、按房间拼路线、结算时卡的去留、出售跳过门禁卡 | 已实现，见下文[运行规则](#运行规则)；汽车旅馆二层、芝邦邦餐厅、仓储中心二层板房都已经 MCP 实机跑通整条流程，原始记录未归档 |
| 设置页的模式、地图、房间与保留张数 | 已实现，见[设置页](overview.md#设置页) |
| 自动挑卡、仓库没卡时结束任务 | 已实现，见下文[挑卡](#挑卡)；按保留张数清点、挑卡、清点到保留张数后正常结束任务，已在三个房间经 MCP 实机跑通，原始记录未归档；结算仓库就地挑卡尚未确认 |

## 房间

房间登记在 `bagel/assets/game_data/bagel/keycard_rooms.yml`，随插件发布、只读：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定标识。路线文件和开启选择用它引用房间 |
| `name` | 显示名称，与游戏刷卡提示的房间名一致 |
| `layer`、`x`、`y` | 房间入口：所在完整分层与全局坐标 |
| `radius` | 接缝半径，单位为地图像素 |
| `initial_room_route` | 新装或升级后尚未配置的房间自动开启的默认房间段标识；未填写表示不开启 |
| `initial_entry_routes` | 随默认房间段自动开启的入口段，按出生点标识填写路线标识；未填写表示全部关闭 |

房间入口是入口段与房间段的接缝，取房卡门外一小段的途径点，不取房卡门本身，让刷卡点留在房间段里。

| 标识 | 显示名称 | 房间入口 | 接缝半径 |
| --- | --- | --- | --- |
| `windworn_motel_2f` | 风蚀公路汽车旅馆二层 | `城郊幻境/Custom3 (160,319)` | 20 |
| `bunless_zhibangbang` | 无力野人镇芝邦邦餐厅 | `城郊幻境/Custom4 (950,133)` | 20 |
| `bunless_storage_2f` | 无力野人镇仓储中心二层板房 | `城郊幻境/Custom4_1 (1077,189)` | 20 |

芝邦邦餐厅的入口在餐厅大堂里、房卡门西侧，坐标取自野人镇_西出生的录像离线定位。房卡门在大堂东墙，刷卡处在门框北侧，录像里在 `(958,128)` 刷开；门后小间里有一个公文包（`(968,137)`），电子保险箱与机械保险箱并排在 `(982,138)`。

芝邦邦餐厅的房间段刷卡后先退回门外 `(953,132)`，再向东穿门进小间。门洞很窄，顺利穿过时位置在 y 130–132。退回后原地掉头，位置多次偏到 y≈134；这时直接朝门内的点走，会在 `(959,134)` 顶住门框南侧。所以门洞中线附近 `(960,131)` 放一个途径点，先把角色拉回门洞中线再进门。

仓储中心二层板房在仓储中心二楼，二楼用 `城郊幻境/Custom4_1` 定位。入口在二楼走廊上、房卡门西侧，坐标取自野人镇_东出生的录像离线定位。去板房要先进仓储中心一楼，上两段楼梯：第一段从 `(1034,181)` 向南到平台 `(1033,225)`，第二段从 `(1046,222)` 向北到楼梯顶。房卡门在 `(1083,192)` 刷开。板房里有两个机械保险箱和一个电子保险箱：一个机械保险箱在南墙 `(1095,213)`，电子保险箱在它北边 `(1094,207)`，另一个机械保险箱在房卡门内侧 `(1084,189)`。

仓储中心二层板房的默认房间段在 `(1084,195)` 刷卡，随后经 `(1093,198)` 进入板房，再到 `(1095,175)`。接近容器前另设途径点，当前点位以随插件发布的路线文件为准。

## 入口段与房间段

开房卡路线分两段存，执行前拼成一条：

| 段 | 起点 | 终点 | 绑定 | 每份对应 |
| --- | --- | --- | --- | --- |
| 入口段 | 出生点 | 房间入口 | 出生点和房间 | 一个出生点去一个房间 |
| 房间段 | 房间入口 | 搜完最后一个容器 | 房间，不绑定出生点 | 一个房间 |

同一房间的房间段只存一份，所有出生点共用。改房间内的点位只改房间段，不用逐条同步。

两段都是普通路线文件，多一个 `keycard` 字段标记段类型（路线文件的其余字段见[路线文件](routes.md#路线文件)）：

```json
{
  "version": 2,
  "route_id": "custom_<房间段>",
  "name": "汽车旅馆二层-房间段",
  "spawn_id": "",
  "keycard": {"room": "windworn_motel_2f", "segment": "room"},
  "points": [
    {"x": 160, "y": 319, "layer": "城郊幻境/Custom3", "kind": "beacon"},
    {"x": 153, "y": 319, "layer": "城郊幻境/Custom3_1", "kind": "keycard_door"}
  ]
}
```

- `segment` 为 `entry`（入口段）或 `room`（房间段）。没有 `keycard` 字段的是跑刀路线。
- 房间段的 `spawn_id` 必须为空；入口段和跑刀路线必须绑定出生点。
- 段标记创建后不变。编辑器不提供把跑刀路线改成段、或在两种段之间转换的操作。

### 能否使用

开启某一段、拼接和试跑时都检查以下条件。不满足时，开启被拒绝，拼接报错，正式运行拒绝开始。

| 段 | 条件 |
| --- | --- |
| 房间段 | 首点是途径点，与房间入口同层，并在接缝半径内；段内至少有一个房卡门点 |
| 入口段 | 满足[路线能否开始](routes.md#路线能否开始)；末点与房间入口同层，并在接缝半径内；段内不能有房卡门点 |

入口段不允许房卡门点，免得同一扇门刷两次。保存自定义段时只检查首点（房间段对齐房间入口，入口段对齐出生点），其余条件留到开启时检查，所以补点过程中的半成品可以保存。

### 拼接

拼出的路线依次是入口段全部点、房间段全部点。入口段末点与房间段首点完全相同（同一个入口途径点）时只保留一个。拼出的路线只在内存里使用，不写盘：

- 标识为 `入口段标识+房间段标识`，名称为 `入口段名称 + 房间段名称`。日志与统计按这个组合区分。
- 两段都是默认路线时才算默认来源，否则算自定义。

执行器拿到拼好的路线后与跑刀路线走同一套导航和交互，不感知分段。

## 默认路线

插件在 `bagel/assets/game_data/bagel/routes/` 发布 3 个房间段和 6 个入口段。文件标识与显示名称均为对应段名加 `-默认`，后缀为 `.sample.route.json`。默认段只读，复制后可以修改；点位以这些路线文件为准。

| 房间 | 房间段点数 | 入口段与点数 |
| --- | --- | --- |
| 汽车旅馆二层 | 10 | 风蚀公路_高：9；风蚀公路_低：6 |
| 芝邦邦餐厅 | 10 | 野人镇_东：5；野人镇_西：8 |
| 仓储中心二层板房 | 15 | 野人镇_东：11；野人镇_西：12 |

巴哈姆特仓库的出生点没有默认入口段。抽到没有开启入口段的出生点，按不支持处理并退出重开。

房间清单的 `initial_room_route` 和 `initial_entry_routes` 指定自动开启的默认段。首次使用时开启；升级时为尚未配置的房间补齐开启选择。只接受房间、出生点绑定正确且通过段校验的默认路线；房间段不可用时，该房间不开启任何段。

## 开启选择

开启选择写在 `route_settings.yml` 的 `keycard_routes` 下，与跑刀的 `active_routes` 分开（文件的其余规则见[开启选择](routes.md#开启选择)）：

```yaml
keycard_routes:
  windworn_motel_2f:
    room:
      source: custom
      route_id: custom_<房间段>
    entries:
      windworn_highway_high:
        source: custom
        route_id: custom_<高出生点入口段>
      windworn_highway_low:
        source: custom
        route_id: custom_<低出生点入口段>
```

每个房间开启一条房间段，每个出生点开启一条去该房间的入口段。首次使用时按房间清单开启上述默认段；升级时，`keycard_routes` 中没有记录的房间也会自动开启默认段并写回配置。旧配置没有 `keycard_routes` 或该映射为空时，会开启全部可用的默认段。

已经有房间记录时保留整份选择，包括自定义路线、关闭的房间段和入口段；不补齐该房间缺少的入口段。用户手动关闭或删除开启中的段后，仍会留下房间记录，下次读取不会自动重新开启。跑刀的 `active_routes` 不受开房卡升级影响。损坏配置报错，不用默认选择覆盖。没有任何开房卡选择时不写出该字段。

| 条件 | 处理 |
| --- | --- |
| 正式运行时，出生点没有开启去目标房间的入口段 | 按出生点不支持处理，退出重开 |
| 开启了入口段，但房间没有开启房间段 | 房间的选择标记为无效，正式运行拒绝开始 |
| 引用的段不存在、损坏、段类型或房间不符、接不上入口 | 同上，标记为无效，不自动换成其他段 |
| 记录了未登记的房间 | 忽略该记录，编辑器显示提示 |
| 删除开启中的段 | 先把对应位置改为关闭并写入，再删除文件 |
| 入口段或房间段当作跑刀路线开启 | 拒绝 |

## 试跑

| 试跑对象 | 起点 | 执行内容 |
| --- | --- | --- |
| 房间段 | 角色站在房间入口接缝半径内 | 只跑房间段。房间入口代替出生点完成起点锚定 |
| 入口段 | 角色站在绑定出生点识别半径内 | 接上该房间当前开启的房间段一起跑；房间没有开启房间段时拒绝试跑 |

试跑不改变开启选择，关闭的段也可以试跑。

## 运行规则

配置 `mode: keycard` 并在 `keycard_room` 填房间标识后，应用按开房卡模式运行（配置字段见[配置](overview.md#配置bagelconfig)）。与跑刀相同的部分（退出、入仓核验、出售间隔、连续失败计数）不再重复。

**启动检查。** 房间必须已登记；该房间的开启选择必须有效（见[开启选择](#开启选择)）；必须开启了房间段，且至少一个出生点开启了入口段；保留张数大于 0 时，该房间必须有门禁卡图标模板。任一不满足就拒绝启动。

**入场。** 进城郊幻境，难度固定高危，零投资。首次入场先清空全部携带，与跑刀相同。之后的携带要求为背包和装备槽为空、安全箱正好 1 件，见[入场与携带核验](entry.md#入场与携带核验)。安全箱为空时，先从备战「前往仓库」[挑卡](#挑卡)，回到备战后重新核对；本次入场只挑一次。核对通过后，应用记为「安全箱里有卡」。挑卡时仓库已没有该房间的卡，或只剩保留张数，不进局，正常结束任务。

**局内。** 出生点开启了去目标房间的入口段时，执行器跑「入口段 + 房间段」；没开启时按出生点不支持退出重开，卡留在安全箱。刷卡处的持卡计数首位为 0（没带这个房间的卡）时，退出、全部入仓，然后停止任务。

**结算时卡的去留。**

| 本局情况 | 处理 | 下一步 |
| --- | --- | --- |
| 出生点不支持，退出重开 | 不入仓，卡留在安全箱 | 继续入场 |
| 刷开了房卡门（无论成败） | 卡已用掉，安全箱照常入仓，然后就地挑下一局的卡 | 成功局按跑刀规则计成功；继续入场 |
| 失败局，没刷门，安全箱只占 1 格，且失败次数未达上限 | 不入仓，卡留在安全箱 | 继续入场 |
| 失败局，没刷门，安全箱不止 1 格或读不清 | 全部入仓，卡回到仓库，然后就地挑卡 | 继续入场 |
| 失败局，失败次数已达上限 | 全部入仓，卡存回仓库，不挑卡 | 按连续失败上限停止 |
| 本局结算后达到成功上限或连续 3 局空箱 | 照常入仓，不挑卡 | 按跑刀规则结束 |
| 持卡计数为 0 | 全部入仓 | 停止任务 |

结算仓库就地挑卡时仓库已没有该房间的卡，或只剩保留张数：本局照常返回，随后正常结束任务。就地挑卡因其他原因没挑上时只写日志，下一局入场发现安全箱为空会在备战再挑一次。

结算仓库开新局前的安全箱核对，在「安全箱里有卡」时允许占 1 格，其余情况仍要求为空。

成功的定义与跑刀相同：路线走完且有物资入仓。房间段必须含房卡门点，路线走完就意味着刷开了门，所以成功即「刷卡成功且有物资入仓」。

**出售。** 不卖门禁卡，见[出售方案](settle.md#出售方案)。

## 挑卡

挑卡由 `bagel/operation/pick_keycard.py` 执行，画面几何在 `bagel/vision/keycard_pick.py`。备战仓库和结算仓库的网格、分页与安全箱位置相同，两处共用一套流程；从备战进入时先点「前往仓库」，挑完点左上返回。

1. 核对仓库安全箱为空。不为空就不挑，按失败处理。
2. 点网格上方类型筛选的「门禁卡」，直到仓库标题（原为「全部(已用/容量)」）含「门禁」；点 4 次仍不含就写警告，按当前筛选继续。
3. 保留张数（`keycard_reserve`）大于 0 时先清点，见下文[按保留张数清点](#按保留张数清点)。仓库里该房间的卡不多于保留张数就不挑，按仓库没有可用的卡结束任务。
4. 点分页页签，从第 1 页开始。点之前先读页签状态（见下文[分页页签](#分页页签)）：要去的页是暗色或锁定，就按已翻完全部分页处理，不去点。点完后等该页签显示为选中，没选中就重点，共点 3 次仍没选中就停止并保留现场。不用「点了以后网格变没变」判断翻没翻页：相邻两页都是整块同款卡时网格看起来一样，会把能翻的页误判成翻不过去，漏掉后面所有页。
   翻到一页后先向上滚，唤出 ▼ 提示：切页后 ▼ 还是这一页上次离开时的状态（例如上次滚到底时它已消失），要滚动过才更新，不滚就会把还能滚的页当成到底。切到另一页时列表在顶部，向上滚 1 条不会动，只用来刷新 ▼；点的是已选中的页（刚打开仓库，或清点完回到同一页挑卡）时列表可能停在中间，向上滚 5 条回到顶部（一页最多向下滚 3 次，每条一行；滚离顶部后画面没有顶部提示，只能靠命令数）。命令发完后等第 1 行落回顶部位置（行心 y≈321，容差 6 px），且相邻两次截图的行和 ▼ 都不变，最多再等 6 次，等不到就停止并保留现场；列表在顶部时再向上滚会回弹，要等一会儿。停稳后 ▼ 不在，可能是命令丢了，也可能本页不超过一屏，补发向上滚动，共 3 条仍不在就按本页滚不动处理，只看这一屏。
   万一点到未解锁的分页，会弹出「可通过以下途径解锁仓储枢纽容量」，点「确认」关掉，按已翻完全部分页处理。
5. 在当前屏找出有物品的格子，按与目标卡图标的相似度从高到低排序，取相似度不低于 0.85 的前 8 格。没有该房间的图标模板时，按从上到下、从左到右逐格核对。
6. 逐格点开，OCR 浮窗标题和类型。标题与房间名一致（允许错漏一个字）且类型含「门禁」，才点浮窗的「放入安全箱」。
7. 点完后最多看 4 帧，安全箱出现物品即挑卡完成。
8. 当前屏没有目标卡就向下滚一行。滚动前先看浮窗类型标签：还读到「门禁」，说明上一格的浮窗没关，先点网格标题栏空白处 `(1350,239)` 关掉，最多点 3 次，仍关不掉就停止并保留现场。浮窗开着时滚轮滚不动网格。
   - 一条命令一行：每条滚动命令（`scroll` 1 格）正好滚一整行 122 px，向上同理。1 格是实机核对过的；5 格曾在一次游戏重启后一条命令滚了至少 3 行、直接到页底，原因未查明，所以不用多格。所以行心 y 在滚动前后不变，不能靠行的位置判断滚了没有，行号只靠命令数记账。
   - 到底：网格下方居中的 ▼ 提示（`(1414,856)–(1454,872)` 里亮度不低于 200 的像素不少于 100 个）不在了，本页到底，换下一页。▼ 在还能向下滚时约 288，到底后淡出到约 40，最后为 0。
   - 一页最多 8 行（仓库容量 280 = 5 页 × 56 格，每行 7 格），一屏完整显示 5 行，所以一页最多向下滚 3 次。已向下滚 3 次 ▼ 还在，说明记账或画面不对，停止并保留现场。
   - 停稳：滚动后每 0.3 秒截一次图，相邻两次截图里各完整行的行心 y 都不变（容差 1 px）、▼ 状态也没变，才算停稳；最多截 8 次，用完仍在动就按当前画面继续并记警告。停稳后行心对行距取余的相位必须与顶部一致，不一致说明滚动不是整行，停止并保留现场。
   - 滚了没有：游戏截图无损，列表不动时画面逐像素不变。比较滚动前后各完整行、各格（跳过滚轮光标和 ▼ 所在的第 4 列）的灰度，任何一格平均差超过 1 就算滚了一行。画面没变而滚动前相邻两行有不同的卡（同一列 6×6 缩略图平均差不低于 4；实机同款卡 1.5–2.3、不同的卡 5.8 以上），说明真滚了画面一定会变，是命令丢了，重发，连续 3 次都没动就停止并保留现场，不当成到底。画面没变、可见各行又全是同款卡时分不出，按「▼ 在命令前存在，命令生效就正好滚一行」记一行并写日志，见[已知限制](#已知限制)。
   7 页都翻完，或下一页的页签是暗的或锁定，按仓库没有该房间的卡处理。清点过且清点到卡却没挑到时，不按没卡处理，而是停止并保留现场。
9. 挑到卡、没卡或到保留张数时，先把类型筛选点回「全部」再返回：结算仓库后续的入仓和出售按「全部」标题读仓库容量。停止并保留现场的情况不切回。

### 按保留张数清点

保留张数是仓库里不动用的该房间门禁卡张数。0 表示用到没卡为止，不清点。大于 0 时，每次挑卡前都把仓库全部页看一遍：

1. 逐页切换，先向上滚唤出 ▼，再逐行向下滚，翻页和到底的判定与挑卡相同。
2. 每屏只看图标，不点开浮窗、不读标题。图标相似度不低于 0.95 才计 1 张。
3. 按绝对行号记账，不比较行内容：向上滚动停稳后的第一屏建立记账，第 1 个完整行记为第 0 行；之后每记一次向下滚动，行号加 1，当前屏的行号 = 已向下滚的行数 + round((行心 y − 首行 y) ÷ 122)。每页每个行号只记一次，同一行在不同位置被多次看到时取读数最大的一次（靠近列表上下边缘的卡片会被调暗，单次读数可能偏低），两次读数不同会写日志。清点总数是各行读数之和。日志「贝果挑卡清点」逐屏写出已向下滚的行数、本屏行号和 ▼ 像素数。
4. 全部页看完后，清点张数不多于保留张数就结束任务；多于保留张数才从第 1 页开始挑。

清点不含安全箱里的卡。挑卡时安全箱必须为空，所以清点数就是仓库里的全部。

日志「贝果挑卡：清点完毕」写出清点张数，以及相似度在 0.85 到 0.95 之间、没计入的格子分数，供标定 0.95 这条线。清点张数不多于保留张数而结束时，各屏网格拼成一张图存到截图目录，文件名以 `BagelKeycardCount` 开头，日志写出路径。

## 已知限制

- 接缝半径 20 地图像素是按汽车旅馆二层的室内尺度定的，芝邦邦餐厅和仓储中心二层板房沿用，尚未标定。
- 芝邦邦餐厅的默认段采用当前路线文件中的点位。野人镇_东入口段最初由出生段与野人镇_西进大堂段衔接得到；当前东、西入口段是否都经过完整实机验收，缺少已归档记录，尚未确认。门后小间和保险箱附近常有地面拾取物，执行器先捡走再开容器，见[地面拾取物](container.md#地面拾取物)。
- 仓储中心二层板房的默认段采用当前路线文件中的点位。从电子保险箱去门内机械保险箱时，路线会经过板房北侧；`Custom4_1` 底图未画出全部可通行开口。野人镇_东、西两份入口段与当前房间段的完整实机验收范围缺少已归档记录，尚未确认。
- 默认段的离线核对覆盖文件加载、出生点与房间绑定、首末点接缝、首次开启选择及 6 种组合的拼接，不表示当前发布点位已完成实机验收。
- 首次入场一律清空携带，用户事先放进安全箱的卡也会存回仓库，再由挑卡重新放入。
- 标题读不到「门禁」时按当前筛选继续找。
- 备战仓库里的挑卡已实机跑通。结算仓库的浮窗按钮是否与备战仓库相同，尚未确认；浮窗没关可能挡住随后的「返回研究站」。
- 汽车旅馆二层的图标模板取自有损录屏。相似度低于 0.85 的格子不会点开，若实机同款卡整体偏低，就只滚动和翻页，最后按仓库没有卡结束。
- 只认未使用的卡：浮窗里的剩余次数（如「1/1」）不读，仓库里若有用过的同名卡也可能被挑中。
- 挑卡最多 300 秒，要清点时 480 秒；格子多、相似卡多时可能超时。
- 清点的 0.95 只按一次实机截图标定，别的房间的卡、别的仓库排布尚未核对。同款卡低于 0.95 会少数，任务提前结束；别款卡高于 0.95 会多数，用掉的卡比设想的多。
- 字母徽标的位置 `(12,4)–(32,28)` 按汽车旅馆二层的模板定，默认各房间的卡版式相同，尚未用其他房间的卡核对。
- 清点不处理少见的丢命令组合：可见 5 行全是同款卡时恰好丢了一条向下滚动命令，会多记一行；向上滚动命令连丢 3 条，会把还能滚的页当成不超过一屏，少数。实机丢滚动命令的频率尚未确认。
- 滚轮在指定坐标发出，运行时移动鼠标会让滚轮落到别处，清点会出错或停下。
- 清点的实机验收覆盖：管理员权限、进程内运行（未走 MCP），备战仓库 1920×1080，门禁卡筛选后 3 页满 8 行加第 4 页 1 行，三个房间的模板，张数与逐行人工核对一致，含整页同款卡、跨页连续的同款卡和只有一行的末页。尚未实机验收：6–7 行的页、少于 5 行但多于 1 行的页、点已选中的页时列表停在中间、结算仓库。按保留张数清点后接着挑卡，已在三个房间经 MCP 实机跑通，原始记录未归档。
- 游戏是管理员进程，自动化进程没有管理员权限时点击和滚轮都会被系统拦下（UIPI），表现为筛选点不动、列表滚不动。
- 清点只按图标，不读浮窗里的剩余次数，用过的同名卡也会计入。
- 用户手动停止或程序异常停止时，不会把安全箱里的卡存回仓库。
- 编辑器在地图上画出房间入口和接缝半径，但不提供新增或移动房间的操作；房间清单只能通过修改 `keycard_rooms.yml` 维护。
