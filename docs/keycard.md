# 开房卡

开房卡模式在城郊幻境高危局带一张门禁卡入场，走到对应房间刷卡进门，只搜房间内的容器后退出。本文集中说明开房卡专属的数据和执行规则；与跑刀共用的部分只给链接。

当前实现范围：

| 部分 | 状态 |
| --- | --- |
| 房卡门点类型与刷卡处长按 | 已实现，见[刷卡处](container.md#刷卡处) |
| 房间清单、入口段与房间段、拼接与开启选择 | 已实现，本文下面各节 |
| 编辑器的分组、开关、新增、录制与试跑 | 已实现，见[网页路线编辑器](editor.md#开房卡的段) |
| 配置 `mode`、`keycard_room`、`keycard_reserve`，启动检查、城郊幻境入场、带卡核对、按房间拼路线、结算时卡的去留、出售跳过门禁卡 | 已实现，见下文[运行规则](#运行规则)，尚未实机验收 |
| 设置页的模式、地图、房间与保留张数 | 已实现，见[设置页](overview.md#设置页) |
| 自动挑卡、仓库没卡时结束任务 | 已实现，见下文[挑卡](#挑卡)，尚未实机验收 |

## 房间

房间登记在 `bagel/assets/game_data/bagel/keycard_rooms.yml`，随插件发布、只读：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定标识。路线文件和开启选择用它引用房间 |
| `name` | 显示名称，与游戏刷卡提示的房间名一致 |
| `layer`、`x`、`y` | 房间入口：所在完整分层与全局坐标 |
| `radius` | 接缝半径，单位为地图像素 |

房间入口是入口段与房间段的接缝，取房卡门外一小段的途径点，不取房卡门本身，让刷卡点留在房间段里。

| 标识 | 显示名称 | 房间入口 | 接缝半径 |
| --- | --- | --- | --- |
| `windworn_motel_2f` | 风蚀公路汽车旅馆二层 | `城郊幻境/Custom3 (160,319)` | 20 |

无力野人镇芝邦邦餐厅、无力野人镇仓储中心二层板房尚未登记，要等有录像确定入口坐标后再加。

## 入口段与房间段

开房卡路线分两段存，执行前拼成一条：

| 段 | 起点 | 终点 | 绑定 | 每份对应 |
| --- | --- | --- | --- | --- |
| 入口段 | 出生点 | 房间入口 | 出生点和房间 | 一个出生点去一个房间 |
| 房间段 | 房间入口 | 搜完最后一个容器 | 房间，不绑定出生点 | 一个房间 |

同一房间的房间段只存一份，所有出生点共用。改房间内的点位只改房间段，不用逐条同步。

两段都是普通路线文件，多一个 `keycard` 字段标记段类型（路线文件的其余字段见[路线文件](routes.md#路线文件)）：

```json
{
  "version": 2,
  "route_id": "custom_<房间段>",
  "name": "汽车旅馆二层-房间段",
  "spawn_id": "",
  "keycard": {"room": "windworn_motel_2f", "segment": "room"},
  "points": [
    {"x": 160, "y": 319, "layer": "城郊幻境/Custom3", "kind": "beacon"},
    {"x": 153, "y": 319, "layer": "城郊幻境/Custom3_1", "kind": "keycard_door"}
  ]
}
```

- `segment` 为 `entry`（入口段）或 `room`（房间段）。没有 `keycard` 字段的是跑刀路线。
- 房间段的 `spawn_id` 必须为空；入口段和跑刀路线必须绑定出生点。
- 段标记创建后不变。编辑器不提供把跑刀路线改成段、或在两种段之间转换的操作。

### 能否使用

开启某一段、拼接和试跑时都检查以下条件。不满足时，开启被拒绝，拼接报错，正式运行拒绝开始。

| 段 | 条件 |
| --- | --- |
| 房间段 | 首点是途径点，与房间入口同层，并在接缝半径内；段内至少有一个房卡门点 |
| 入口段 | 满足[路线能否开始](routes.md#路线能否开始)；末点与房间入口同层，并在接缝半径内；段内不能有房卡门点 |

入口段不允许房卡门点，免得同一扇门刷两次。保存自定义段时只检查首点（房间段对齐房间入口，入口段对齐出生点），其余条件留到开启时检查，所以补点过程中的半成品可以保存。

### 拼接

拼出的路线依次是入口段全部点、房间段全部点。入口段末点与房间段首点完全相同（同一个入口途径点）时只保留一个。拼出的路线只在内存里使用，不写盘：

- 标识为 `入口段标识+房间段标识`，名称为 `入口段名称 + 房间段名称`。日志与统计按这个组合区分。
- 两段都是默认路线时才算默认来源，否则算自定义。

执行器拿到拼好的路线后与跑刀路线走同一套导航和交互，不感知分段。

## 开启选择

开启选择写在 `route_settings.yml` 的 `keycard_routes` 下，与跑刀的 `active_routes` 分开（文件的其余规则见[开启选择](routes.md#开启选择)）：

```yaml
keycard_routes:
  windworn_motel_2f:
    room:
      source: custom
      route_id: custom_<房间段>
    entries:
      windworn_highway_high:
        source: custom
        route_id: custom_<高出生点入口段>
      windworn_highway_low:
        source: custom
        route_id: custom_<低出生点入口段>
```

每个房间开启一条房间段，每个出生点开启一条去该房间的入口段。`keycard_routes` 是可选项：旧配置没有它时按全部关闭处理，没有任何开房卡选择时也不写出。

| 条件 | 处理 |
| --- | --- |
| 正式运行时，出生点没有开启去目标房间的入口段 | 按出生点不支持处理，退出重开 |
| 开启了入口段，但房间没有开启房间段 | 房间的选择标记为无效，正式运行拒绝开始 |
| 引用的段不存在、损坏、段类型或房间不符、接不上入口 | 同上，标记为无效，不自动换成其他段 |
| 记录了未登记的房间 | 忽略该记录，编辑器显示提示 |
| 删除开启中的段 | 先把对应位置改为关闭并写入，再删除文件 |
| 入口段或房间段当作跑刀路线开启 | 拒绝 |

## 试跑

| 试跑对象 | 起点 | 执行内容 |
| --- | --- | --- |
| 房间段 | 角色站在房间入口接缝半径内 | 只跑房间段。房间入口代替出生点完成起点锚定 |
| 入口段 | 角色站在绑定出生点识别半径内 | 接上该房间当前开启的房间段一起跑；房间没有开启房间段时拒绝试跑 |

试跑不改变开启选择，关闭的段也可以试跑。

## 运行规则

配置 `mode: keycard` 并在 `keycard_room` 填房间标识后，应用按开房卡模式运行（配置字段见[配置](overview.md#配置bagelconfig)）。与跑刀相同的部分（退出、入仓核验、出售间隔、连续失败计数）不再重复。

**启动检查。** 房间必须已登记；该房间的开启选择必须有效（见[开启选择](#开启选择)）；必须开启了房间段，且至少一个出生点开启了入口段；保留张数大于 0 时，该房间必须有门禁卡图标模板。任一不满足就拒绝启动。

**入场。** 进城郊幻境，难度固定高危，零投资。首次入场先清空全部携带，与跑刀相同。之后的携带要求为背包和装备槽为空、安全箱正好 1 件，见[入场与携带核验](entry.md#入场与携带核验)。安全箱为空时，先从备战「前往仓库」[挑卡](#挑卡)，回到备战后重新核对；本次入场只挑一次。核对通过后，应用记为「安全箱里有卡」。挑卡时仓库已没有该房间的卡，或只剩保留张数，不进局，正常结束任务。

**局内。** 出生点开启了去目标房间的入口段时，执行器跑「入口段 + 房间段」；没开启时按出生点不支持退出重开，卡留在安全箱。刷卡处的持卡计数首位为 0（没带这个房间的卡）时，退出、全部入仓，然后停止任务。

**结算时卡的去留。**

| 本局情况 | 处理 | 下一步 |
| --- | --- | --- |
| 出生点不支持，退出重开 | 不入仓，卡留在安全箱 | 继续入场 |
| 刷开了房卡门（无论成败） | 卡已用掉，安全箱照常入仓，然后就地挑下一局的卡 | 成功局按跑刀规则计成功；继续入场 |
| 失败局，没刷门，安全箱只占 1 格，且失败次数未达上限 | 不入仓，卡留在安全箱 | 继续入场 |
| 失败局，没刷门，安全箱不止 1 格或读不清 | 全部入仓，卡回到仓库，然后就地挑卡 | 继续入场 |
| 失败局，失败次数已达上限 | 全部入仓，卡存回仓库，不挑卡 | 按连续失败上限停止 |
| 本局结算后达到成功上限或连续 3 局空箱 | 照常入仓，不挑卡 | 按跑刀规则结束 |
| 持卡计数为 0 | 全部入仓 | 停止任务 |

结算仓库就地挑卡时仓库已没有该房间的卡，或只剩保留张数：本局照常返回，随后正常结束任务。就地挑卡因其他原因没挑上时只写日志，下一局入场发现安全箱为空会在备战再挑一次。

结算仓库开新局前的安全箱核对，在「安全箱里有卡」时允许占 1 格，其余情况仍要求为空。

成功的定义与跑刀相同：路线走完且有物资入仓。房间段必须含房卡门点，路线走完就意味着刷开了门，所以成功即「刷卡成功且有物资入仓」。

**出售。** 不卖门禁卡，见[出售方案](settle.md#出售方案)。

## 挑卡

挑卡由 `bagel/operation/pick_keycard.py` 执行，画面几何在 `bagel/vision/keycard_pick.py`。备战仓库和结算仓库的网格、分页与安全箱位置相同，两处共用一套流程；从备战进入时先点「前往仓库」，挑完点左上返回。

1. 核对仓库安全箱为空。不为空就不挑，按失败处理。
2. 点网格上方类型筛选的「门禁卡」，直到仓库标题（原为「全部(已用/容量)」）含「门禁」；点 4 次仍不含就写警告，按当前筛选继续。
3. 保留张数（`keycard_reserve`）大于 0 时先清点，见下文[按保留张数清点](#按保留张数清点)。仓库里该房间的卡不多于保留张数就不挑，按仓库没有可用的卡结束任务。
4. 点分页页签，从第 1 页开始。每切到一页，先向上滚到网格不再变化，从本页顶部开始找。点到未解锁的分页会弹出「可通过以下途径解锁仓储枢纽容量」，点「确认」关掉，按已翻完全部分页处理。
5. 在当前屏找出有物品的格子，按与目标卡图标的相似度从高到低排序，取相似度不低于 0.85 的前 8 格。没有该房间的图标模板时，按从上到下、从左到右逐格核对。
6. 逐格点开，OCR 浮窗标题和类型。标题与房间名一致（允许错漏一个字）且类型含「门禁」，才点浮窗的「放入安全箱」。
7. 点完后最多看 4 帧，安全箱出现物品即挑卡完成。
8. 当前屏没有目标卡就在网格上向下滚 5 格；滚动后网格没变说明本页到底，换下一页。翻页后网格没变（锁定页或没有更多页），或 7 页都翻完，按仓库没有该房间的卡处理。清点过且清点到卡却没挑到时，不按没卡处理，而是停止并保留现场。
9. 挑到卡、没卡或到保留张数时，先把类型筛选点回「全部」再返回：结算仓库后续的入仓和出售按「全部」标题读仓库容量。停止并保留现场的情况不切回。

| 画面位置 | 坐标（1080p） |
| --- | --- |
| 网格 7 列格心 x | 1120 起每列加 104 |
| 网格行心 y | 不写死，按卡片底色每次现找；未滚动时为 321、443、565、687、809 |
| 类型筛选「全部」/「门禁卡」 | (1100,50) / (1655,50)；门禁卡是门形图标，在「贵重物品」与「其他」之间 |
| 分页页签 1–7 | y=143，x 为 1100、1211、1321、1432、1542、1653、1763 |
| 未解锁分页提示的「确认」 | `(880,635,1090,700)` |
| 浮窗标题 / 类型 / 「放入安全箱」 | `(605,228,862,268)` / `(605,268,760,298)` / `(800,718,988,766)` |

浮窗位置固定在网格左侧，不随点的格子移动。坐标和流程取自用户录屏，素材见[门禁卡与刷卡处素材](materials/keycard/README.md)。

图标模板放在 `bagel/assets/template/bagel/keycard_<房间标识>/raw.png`，目前只有汽车旅馆二层，裁自录屏。挑卡时只用它排序，最终挑哪张以浮窗标题为准。

相似度由两项取较低者：

- 整张卡面：两边先做半径 1.5 的高斯模糊再比。不模糊时，同款卡因所在行不同，相似度在 0.93–0.99 之间浮动。整张卡面分得开底色和图案，分不开只差字母的卡。
- 字母徽标：模板左上 `(12,4)–(32,28)` 一块，两边模糊 1.0 再比。它分得开 A–E，分不开同字母、不同图案的卡。

按一次实机清点截图离线核对（汽车旅馆二层，B 字、橙色跑人图案）：同款卡 0.978–0.987；同图案的 D 卡约 0.90；同字母、红色图案的 B 卡约 0.86；其他门禁卡 0.82 以下。

### 按保留张数清点

保留张数是仓库里不动用的该房间门禁卡张数。0 表示用到没卡为止，不清点。大于 0 时，每次挑卡前都把仓库全部页看一遍：

1. 逐页切换，滚回顶部，逐屏向下滚，翻页和到底的判定与挑卡相同。
2. 每屏只看图标，不点开浮窗、不读标题。图标相似度不低于 0.95 才计 1 张。
3. 滚动前后会有行重复出现。滚动不按整行对齐，同一行在两屏的行心可差十几像素，滚到顶边的行还会被裁掉一截。所以每行按各自的行心取上下 24 像素的灰度网格条，比较时容许上下错位 8 像素，取最小平均差。滚动前最后几行与滚动后最前几行逐行都不超过 6.5 时，认作同一批行，不重复计数。
4. 全部页看完后，清点张数不多于保留张数就结束任务；多于保留张数才从第 1 页开始挑。

清点不含安全箱里的卡。挑卡时安全箱必须为空，所以清点数就是仓库里的全部。

日志「贝果挑卡：清点完毕」写出清点张数，以及相似度在 0.85 到 0.95 之间、没计入的格子分数，供标定 0.95 这条线。清点张数不多于保留张数而结束时，各屏网格拼成一张图存到截图目录，文件名以 `BagelKeycardCount` 开头，日志写出路径。

## 已知限制

- 接缝半径 20 地图像素是按汽车旅馆二层的室内尺度定的，尚未针对其他房间标定。
- 发布的默认路线里还没有开房卡的段，首次使用不会自动开启任何段。
- 首次入场一律清空携带，用户事先放进安全箱的卡也会存回仓库，再由挑卡重新放入。
- 门禁卡筛选是否跨分页生效、筛选后标题的确切文字，尚未实机确认；标题读不到「门禁」时按当前筛选继续找。
- 挑卡尚未实机验收，以下行为都是推断：滚轮每次滚动的距离、点「放入安全箱」后浮窗是否自动关闭、结算仓库的浮窗按钮是否与备战仓库相同。浮窗没关可能挡住随后的「返回研究站」。
- 汽车旅馆二层的图标模板取自有损录屏。相似度低于 0.85 的格子不会点开，若实机同款卡整体偏低，就只滚动和翻页，最后按仓库没有卡结束。
- 只认未使用的卡：浮窗里的剩余次数（如「1/1」）不读，仓库里若有用过的同名卡也可能被挑中。
- 挑卡最多 300 秒，要清点时 480 秒；格子多、相似卡多时可能超时。
- 清点的 0.95 和行比对的 6.5 只按一次实机截图标定，别的房间的卡、别的仓库排布尚未核对。同款卡低于 0.95 会少数，任务提前结束；别款卡高于 0.95 会多数，用掉的卡比设想的多。
- 字母徽标的位置 `(12,4)–(32,28)` 按汽车旅馆二层的模板定，默认各房间的卡版式相同，尚未用其他房间的卡核对。
- 清点时相邻几行内容完全相同或只差字母（例如整行 C 卡与整行 D 卡在灰度条上几乎一样），滚动后可能多认重叠行、少数张数，结果偏保守。
- 清点只按图标，不读浮窗里的剩余次数，用过的同名卡也会计入。
- 用户手动停止或程序异常停止时，不会把安全箱里的卡存回仓库。
- 编辑器在地图上画出房间入口和接缝半径，但不提供新增或移动房间的操作；房间清单只能通过修改 `keycard_rooms.yml` 维护。
